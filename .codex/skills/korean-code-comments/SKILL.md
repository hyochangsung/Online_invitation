# 한국어 코드 설명 주석

사용자가 제공한 파일을 읽고 원본에 한국어 설명 주석을 추가한다. 독자는 코딩 초보자다. 기본 상세 수준은 **함수·로직 단위 설명 + 어려운 문법 추가 설명**이며, 모든 줄에 반복적인 주석을 달지 않는다.

## 대상과 근거 확인

- 프로젝트의 `AGENTS.md`와 대상 경로에 적용되는 지침을 확인한다. 상대 경로는 프로젝트 루트를 기준으로 해석한다.
- 경로가 없거나 여러 파일로 해석되면 정확한 대상을 질문한다. 파일 경로만 제시되고 주석 추가 요청인지 분명하지 않으면 먼저 의도를 확인한다.
- 대상 파일 전체를 읽는다. 설명에 필요한 타입·호출부·직접 참조 파일은 읽을 수 있지만, 수정은 사용자가 지정한 파일에 한정한다.
- 생성 파일, 의존성 파일, 잠금 파일 또는 주석을 허용하지 않는 형식(JSON 등)이 대상이면 바로 수정하지 않고 별도 설명 문서 등 원하는 방식을 질문한다.
- 프레임워크 API의 의미가 불확실하면 해당 버전의 프로젝트 내 문서나 공식 문서를 확인한다. 특히 Next.js는 프로젝트에 포함된 버전별 문서와 지침을 따른다.

## 질문이 필요한 경우

- 코드에서 확인되는 동작과 작성자의 의도를 구분한다. 주석에 확인되지 않은 서비스 규칙, 성능 이점, 보안 보장, 설계 이유를 만들어 넣지 않는다.
- 예를 들어 숫자 `3`을 곱하는 동작은 설명할 수 있지만, 그 숫자가 어떤 업무 기준인지 알 수 없다면 사용자에게 질문한다.
- 질문은 파일 경로·관련 코드·확인할 의미를 짧게 제시한다. 한 번에 관련 질문을 모으고, 답변이 필요한 부분은 주석 추가를 보류한다. 확실한 부분은 먼저 처리할 수 있다.
- 코드만으로 충분히 확인되는 내용이나 사용자가 이미 결정한 설명 수준은 다시 묻지 않는다.
- 버그나 개선점을 발견해도 주석 작업에 섞어 고치지 않는다. 발견한 위치와 내용을 별도로 알린다.

## 주석 작성 방식

- 함수나 컴포넌트 앞에는 역할과 주요 입력·출력을 설명한다. 필요한 경우 데이터가 어디서 들어와 어디로 전달되는지 덧붙인다.
- 함수 내부에는 검증, 데이터 변환, 저장, 상태 갱신, 오류 처리 등 의미 있는 흐름 바로 위에 설명을 둔다. 짧은 코드에서 의미가 겹치면 주석을 합친다.
- 초보자가 이해하기 어려운 비동기 처리, 타입·제네릭, 구조 분해, React 상태와 효과, 서버·클라이언트 경계 등은 실제 코드에 등장할 때만 풀어 설명한다.
- 단순히 코드 이름을 번역하지 말고 이 코드가 하는 일과 주변 흐름에서 맡는 역할을 설명한다. 전문 용어를 사용하면 첫 설명에 쉬운 뜻을 함께 적는다.
- 짧은 문장을 사용한다. 일반 문법 강의나 서비스와 무관한 예시로 파일을 채우지 않는다.
- 기존의 정확한 주석은 유지하고 중복 설명은 피한다. 잘못되었거나 충돌하는 주석은 구현 근거를 확인하고, 의도가 불명확하면 질문한다.
- 파일 언어에 맞는 주석 문법을 사용한다. JSX 내부에는 `{/* 설명 */}`, TypeScript·JavaScript에는 `//` 또는 `/** ... */`, CSS에는 `/* ... */`, SQL에는 `--` 등을 적절히 사용한다. 화면에 설명 문자열을 직접 출력하지 않는다.

예시: 아래 코드가 실제로 전달받은 동반 인원에 본인 한 명을 더하는 경우.

```ts
// 응답자 본인 1명과 동반 인원을 더해 이 응답의 참석 인원을 구한다.
function countAttendees(companionCount: number): number {
  return 1 + companionCount;
}
```

## 동작 유지와 검증

- 실행 코드, 타입, 식별자, import, 데이터, 제어 흐름, 화면 스타일을 변경하지 않는다. 리팩터링, 의존성 추가, 전체 파일 포맷 변경은 이 작업에 포함하지 않는다.
- `"use client"`, `"use server"`, 라이선스, 기존 도구용 주석을 보존한다. `@ts-ignore`, `@ts-expect-error`, ESLint 비활성화, 번들러·빌드용 지시 주석은 추가하거나 변경하지 않는다.
- 변경 전후를 비교해 설명 주석과 그 배치에 필요한 줄바꿈만 바뀌었는지 확인한다. 사용자가 이미 작성한 변경을 되돌리지 않는다.
- 프로젝트 지침에 따라 검증한다. 이 프로젝트의 기본 검사는 `npm run lint`, `npm run typecheck`, `npm run build`다. 환경 제한으로 검사할 수 없으면 실패 이유와 실제 확인 범위를 보고한다. Webpack 대체 검증은 `AGENTS.md`의 지침을 따른다.
- 완료 응답에는 수정한 파일 링크, 설명을 추가한 주요 부분, 검증 결과, 답변을 기다리는 항목만 간단히 정리한다. 실제 실행 검증 없이 동작 유지가 확인되었다고 단정하지 않는다.
